# 论文阅读笔记写作流水线

## §0 本 Skill 是什么

一套「读到一篇新论文 → 产出一篇中文阅读笔记」的方法论流水线，从 97 篇公开博客笔记全量统计 + 逐篇通读中蒸馏而来。
**这是方法论模仿，不是人物扮演**——不模拟人格、不编造作者观点，只复用骨架、句式与格式规范。

本技能的全部脚本与参考资源位于本技能目录内，以下所有命令均以项目根目录为工作目录执行。

- **产出物契约**：单个 `.md` 文件（输出到 `paper-blogs/`）+ `assets/paper-imgs/<论文名>/` 图片目录。不产出多文件、不改动用户已有笔记。
- **领域**：骨架与规范是**通用**的。语料本身偏表格数据机器学习，跨领域（尤其视觉检测）的替换映射见 `references/research/domain-transfer.md`（本技能目录内），实测 95/97 篇手法可迁移。当 `domain-transfer.md` 与本文件冲突时，**以 domain-transfer.md 为准**（它是针对具体领域的特化规则）。
- **篇幅三档**：短 2500 / 标准 4000 / 长 6500 字（语料中位 3770，P25 3071，P75 4845）。

### ⚠ 铁律：不编造

这是唯一一条优先级高于所有风格规范的规则：

> **笔记里的每一个公式、数值、数据集名称、实验结论，都必须能在论文原文中找到出处。**
> 禁止凭领域常识「补全」论文没有给出的公式，禁止推测具体数值，禁止虚构实验结论。
> 信息拿不到就写「未获取」或省略该细节。宁可少写，不可编造。

（实测教训：测试中模型为论文自造了原文不存在的退火与 DropConnect 公式——这比格式不合规严重得多。）

## §1 Agentic Protocol：六步工作流

### Step 0 · 预处理与确认

先尽量补全元信息，**缺项一律标注「未获取」，禁止编造**：标题 / 作者 / 发表期刊或会议 / 年份 / 等级（CCF 等）/ 代码链接 / 作者单位 / 原文 URL。

向用户确认三件事（用户未答则取默认值）：

| 项 | 默认 |
| --- | --- |
| 输出路径与文件名 | `paper-blogs/<英文短标题>.md`（与现有笔记同级） |
| 批判性增补节 | **关**（见 §7） |
| 篇幅档 | 标准 4000 字 |

然后调用以下命令生成 frontmatter + 五节骨架，再往里填：

```
python .qoder/skills/lzk-paper-reading/scripts/new_note.py "paper-blogs/<英文短标题>.md" --title "<论文英文标题>" --category "<分类>"
```

（可选参数：`--date`、`--url`、`--variant 标准|预备知识|survey|方法名`、`--venue 会议|期刊`）

### Step 1 · 通读与切片

通读全文，产出一张**素材切片表**（内部使用，不输出给用户）：

| 切片 | 内容 |
| --- | --- |
| 动机与局限 | 问题定义、现有做法、缺口在哪 |
| 贡献点 | 作者自称的 2-4 条贡献 |
| 方法模块树 | 方法由几个部分组成，数据流怎么走 |
| 实验清单 | 数据集、基线、指标、消融、配图（按序编号占位） |
| 可夸点 | 3-5 个候选，按 §3.5 的优先级排序 |

### Step 2 · 选骨架
按 §2 路由表确定 H2 序列。

### Step 3 · 逐节写作
按 §3 五节契约 + §4 公式图片规范 + §5 表达 DNA 执行。句式直接查 `references/research/phrase-corpus.md`（本技能目录内）。

### Step 4 · 图表落盘
图片存到 `assets/paper-imgs/<论文名>/`，正文用相对路径 `![](../assets/paper-imgs/<论文名>/xx_01.png)` 引用。
可先运行 `python .qoder/skills/html-paper-slides/scripts/pdf_extractor.py <pdf路径> --output-dir assets/paper-imgs/<论文名>` 从 PDF 提取图表（依赖 `pymupdf`、`Pillow`）。

### Step 5 · 自检与交付
跑 `python .qoder/skills/lzk-paper-reading/scripts/check_note.py <文件>`，再人工过 §6 清单，把未通过项改掉后才交付。

## §2 骨架变体路由表

**硬约束**：`研究动机`、`文章贡献` 必须是前两节且必须存在；`优点和创新点` 必须是末节。

| 条件 | 骨架 |
| --- | --- |
| **默认**（42%） | `研究动机 → 文章贡献 → 本文方法 → 实验结果 → 优点和创新点` |
| 需要插入 `预备知识`（25%），满足任一即可：①论文核心 claim 是「把 A 统一 / 等价 / 归约为 B」；②方法依赖读者可能不熟悉的前置概念（如最优传输、三支决策、Gumbel-Softmax）；③方法节会出现 ≥8 个需要集中定义的符号 | 在贡献后、方法前插入 `预备知识` |
| 方法名能统摄方法节全部子节，且无兄弟方案（10%） | `本文方法` → 论文方法名（常与 `实验结果`→`实验分析` **成对改名**） |
| 方法含 ≥3 个可命名子模块（4%） | 方法段拆成多个并列 H2 |
| 含定理/命题，或有复杂度/收敛性论证（4%） | 方法节后加 `理论分析` |
| 实验含消融、可视化、显著性检验等子分析（6%） | 实验结果后加 `XX 分析` |
| 输入是 survey / review（3%） | 见下方 survey 骨架 |
| 短文、早期工作（2%） | 可省略末节，实验末图后直接收尾 |

**survey 骨架**（不写优点节）：

```
<领域>问题 → 本文目标和贡献（列 N 个裸数字编号的完整疑问句）
  → 基本概念和分类方法（建分类体系）→ <逐类算法综述> → 实验研究（末 H3「经验总结」逐条回答前面的问题）
```
逐类写法固定为：**定义句 + 代表工作（加粗名 + 一句机制）+「该方法的优势是……局限在于……」+ 类末 H3「小结」**。
收尾用「分析与展望」：立评估标准 → 重映射范式 → 逐项给局限与未来方向 → 末段「N 个最具潜力的发展方向」。

> 四类变体的真实样貌见 `references/skeleton-variants.md`；完整判据与篇幅数据见 `references/research/skeleton-annotations.md`（均为本技能目录内文件）。

## §3 五节写作契约

### 3.1 研究动机（250-450 字 / 不设 H3）

**目的**：把论文的问题接进读者已有认知，再切出局限。**不写本文怎么解决**（那是贡献节的事）。

- 首句**定义式起手，不带问号**：`<任务> 是 <领域> 的重要问题，表现为 <现象>，导致 <后果>。`
- 第二句转折：`<现有做法> 存在 <局限>。`
- **局限组织法**（先判断局限之间的关系，再选形式，**不要无脑用默认值**）：

  | 局限之间的关系 | 形式 | 语料占比 |
  | --- | --- | --- |
  | **因果递进**（A 导致 B，B 导致 C，逐层收窄到本文靶点） | 综述式铺陈，写成散文链 | **67%** |
  | **并列独立**（几个互不相关的缺陷，或几条待解决的问题） | 编号列表逐条点评 | 20% |
  | **需横向对比**（≥4 类方法流派，读者需要一张表对读） | `\| 现有方法 \| 局限性 \|` 两列表 | 1% |
  | **改进型论文** | 「肯定前作 + 但是 + 编号缺点」 | 常见 |
- 收尾三选一：指认空白「暂未有工作……」/ 列可解决问题「旨在同时解决……两个瓶颈」/ 综述式「综上所述……」。

**禁忌**：不出现公式、不引用具体数值、不写本文方案。

### 3.2 文章贡献（200-350 字 / 一整段散文，禁止分点）

**96% 是散文整段**，句式链固定：

```
针对 <局限>，本文提出了 <模型名>。其核心是 <机制>。首先 <步骤一>，接着 <步骤二>，最终 <步骤三>。实验表明 <结论>。
```

**禁忌**：禁止 `1. 2. 3.` 分点；禁止复述方法细节；禁止在此节放图。
（分点只出现在末尾的「优点和创新点」节，两节分工是：贡献节讲「原文说了什么」，优点节讲「我认为值得学什么」。）

### 3.3 本文方法（1500-2500 字 / H3 数 6-12）

**H3 划分四种逻辑，全篇只用一种**（混合 33% / 按流程步骤 23% / 按模块 18% / 按定义-结构-变体 12%）：

| 逻辑 | 适用 | 例 |
| --- | --- | --- |
| 按模块 | 方法由若干并列组件构成 | 加权树集成 / 可微分割 / 实例权重 / 正则化 |
| 按流程步骤 | 方法是流水线（**视觉类论文多用此逻辑**） | 问题定义 → 特征生成 → 特征选择 → 复杂度分析 |
| 按定义→结构→变体 | 同一对象有多种形态 | 二分类 RandBal → MultiRandBal → OVA/OVO 变体 |
| 混合 | 方法节与实验节各用一种 | 方法按模块，实验按数据集 |

每个 H3 的内部结构，**四要素缺一不可**：

```
① 一句话定性（这个模块是干什么的：「<模块> 的目标是 / 用于 ……」）
② 公式或图
③ 2-4 句解释（机制、为什么这样设计）
④ 与前后模块的关系（它接收什么、输出给谁）——最易漏，务必收尾
```

**禁忌**：不贴论文原图却不解释；不在本节做实验对比；**不要写完公式就戛然而止**。

### 3.4 实验结果（600-1200 字 / 图为主）

固定节奏：**2-3 句文字 + 1 张图**。骨架为：

```
设置（数据集/基线/指标表）→ 主对比 → 消融 → 效率 → 可解释性可视化
```

- **数值只点缀结论句**（全语料 295 个百分数，只出现在结论句），不复述整张表。
- 结论动词只用：`说明` / `可见` / `表明` / `证明了` / `验证了` / `可以看出`。
- **因果语序固定为「现象 → 结论」**：先写观察到的现象或数据，再用「可见 / 表明」引出结论。
  不要写成「由于 <原理>，这说明 <结论>」——原理反推结论在语料里几乎不出现。
- 图注衔接词按频次取用：`如下表所示`(229) / `如下公式`(159) / `如下图所示`(148) / `下图展示了`(75) / `定义如下`(31)。
- 实验结果**几乎全用图片**呈现，不要手抄成 Markdown 大表。
  **例外**：视觉类论文按 `references/research/domain-transfer.md` 执行——定性效果图组先行、定量表佐证，并新增「可视化分析」H3。

**禁忌**：不做批判性评价（见 §7 的可覆盖选项）。

### 3.5 优点和创新点（300-600 字 / 有序列表 2-4 条）

起手句**一字不差**：

```
个人认为，本文有如下一些优点和创新点可供参考学习：
```

- **3 条是绝对主力（57%）**，2 条与 4 条各 14 篇。每条 40-90 字（中位 58）。
- 开头：动词或介词短语（51%）优先，其次模型名或「本文」（18%）。结构为 `做了什么 + 手段 + 达到的效果`。
- 结尾用「。」（并列条目用「；」）。
- 选题优先级：①把 X 改造成**可微/端到端** ②从 Y 视角**统一**了 A 和 B ③**实验丰富、说服力强**；备选池：可解释性 / 计算效率 / 鲁棒泛化 / 特征工程 / 稀疏结构 / 理论证明。
- 价值词：可供参考(86) > 说服力强(11) > 新颖(9) > 巧妙(7) > 有新意、耳目一新、优雅。

> 十类主题的模板句与原文例句见 `references/research/pros-taxonomy.md`（本技能目录内）。

**禁忌**：零负面表述；不写缺点（除非用户开启 §7 的开关）。

## §4 公式、图片、表格规范

### 公式四段式（75% 的语料严格遵守）

```
① 自然语言铺垫句（「XX 定义/计算/更新为：」）
② $...$ 或 $$...$$
③ 「其中 <符号> 是 <含义>；<符号> 为 <含义>。」
④ 语义收束句（「这等价于……」/「直观上……」）——第 ④ 步最易漏
```

> **第 ①②③ 步的公式必须来自论文原文**，不得凭领域常识补全或自造（见 §0 铁律）。

- 铺垫句五种固定说法：`XX 的定义/计算/更新公式如下` / `XX 计算为：` / `形式化为 XX，其中……` / `考虑其中任意一个 XX：` / `在 XX 中，上述 XX 被修改为：`。
- **解释分两档**：≤2 个符号走行内「其中……」顿号罗列；**≥3 个符号或任一条解释超约 20 字，改用「| 符号 | 含义 |」表**。
- 「其中」是全语料最高频衔接词（521 次）。
- 有 LaTeX 源码必须转 LaTeX；只有图片的保留图片，并在笔记末尾登记待办。
- 收束句用「这等价于……／直观上……」。

### 自造算例（转述重于照译的标志动作）

遇到关键机制，自造一个带具体数值的计算样例。**注意：自造的是「数值」，不是「公式」**——
把论文已给出的公式代入自己设定的简单输入，逐步算出中间结果。公式本身仍须来自原文。

结构：

```
①「给出一个简单的例子，假设……」引入 → ② 给极小维度 + 具体数值
→ ③ 编号分步逐步套公式写出中间数值 → ④ 给结果 + 一句「可以看到，……」点明性质
```

### 图片

- 图注**前置**：`……的结构如下图所示` 或 `……的样例如下图所示`。
- **禁止裸图**——每张图后必须跟 ≥1 句解读。
- 伪代码不逐行注解，用「前置输入说明 → 贴图 → 后置概括」三件套，后置用「概括起来就是／主要步骤是」编号列表。

### 表格（只用于四类）

符号表(36) / 方法对比表(34) / 组件↔功能对应表(31) / 消融变体表(15)。39 篇全篇无表，说明表格是按需而非必配。

## §5 表达 DNA 硬约束

**格式**
1. 中英文与数字之间加一个空格（语料合规率 98.0%）。
2. 有序列表一律 `1.` `2.`（优点节 100% 用有序列表）；并列短项与消融用 `-`。
3. 数学一律 LaTeX：行内 `$...$`，独立 `$$...$$`。

**措辞**
4. 主语默认「本文」（922 次，篇均 9.5）；「作者」仅在强调人的主观选择时替换。
5. 几乎不用第一人称「我」（全语料 97 篇仅 2 处，都出现在跨笔记互链时）。
6. **禁用过渡腔**：「值得注意的是」（语料仅 2 次）、「需要说明的是」（0 次）、「值得学习」（0 次，正确说法是「可供参考学习」）。
   同理禁用通用 AI 套话：「综上所述」「首先…其次…最后」「总而言之」「在当今……的背景下」
   「具有重要意义」「为……提供了新思路」——这些在原语料里几乎不出现。
7. **因果语序**：固定为「现象 → 可见结论」，不要写「由于 <原理>，这说明 <结论>」。

**固定件（必须一字不差）**
8. 正文首段免责声明（97/97 一致）：
   > Paper Reading 是从个人角度进行的一些总结分享，受到个人关注点的侧重和实力所限，可能有理解不到位的地方。具体的细节还需要以原文的内容为准，博客中的图表若未另外说明则均来自原文。
9. 论文概况表头 `| 论文概况 | 详细 |`；行标签顺序：标题 → 作者 → （发表期刊 + 期刊等级）**或**（发表会议 + 会议等级，**二选一互斥**）→ 发表年份 → 论文代码。作者单位是表后的独立编号列表，不进表。
10. frontmatter 四字段：`title / category / date / source_url`。
11. **不列参考文献**（语料 0/97）。

## §6 质量自检清单

交付前逐项打勾（先跑 `python .qoder/skills/lzk-paper-reading/scripts/check_note.py <文件>`，机器项以脚本结果为准）：

- [ ] **公式、数值、数据集名、实验结论全部可在论文原文中找到出处，无编造**（§0 铁律）
- [ ] frontmatter 四字段齐全；免责声明一字不差
- [ ] 论文概况表头正确，期刊/会议互斥，作者单位为表后编号列表
- [ ] 五节齐全且顺序正确，符合 §2 选定的骨架
- [ ] 动机节首句非问句，含转折；局限形式按「因果递进/并列独立」判断后选定
- [ ] 贡献节是**一整段散文**，无分点
- [ ] 方法节 H3 划分逻辑唯一；每个 H3 四要素齐全（定性 → 公式图 → 解释 → 前后关系）
- [ ] 每个公式有铺垫句 + 「其中」解释（或符号表）+ 语义收束句
- [ ] 无裸图，每张图后有解读
- [ ] 实验节保持「2-3 句 + 1 图」节奏，因果语序为「现象 → 可见结论」，数值只点缀结论句
- [ ] 优点节 2-4 条有序列表，起手句一字不差，零负面

## §7 诚实边界与可覆盖选项

1. **来源**：从博客园「乌漆WhiteMoon」97 篇公开笔记蒸馏，未获作者授权。是方法论模仿，不代表其本人观点。
2. **领域偏斜**：语料以表格数据 ML 为主（不平衡学习 22 / 决策树森林 21 / 神经网络 14 / 图学习 11），CV 仅 2 篇。写视觉类论文时**不要照搬指标与素材类型**，先查 `references/research/domain-transfer.md`：实验节应从「准确率对比表」切换为**定性效果图组先行、定量表佐证**，并新增「可视化分析」H3。
3. **年代断层**：2023-2024 的 58 篇 LaTeX 公式数为 0（全是截图），2025-2026 的 39 篇公式篇均 62 个。**§4 的公式规范取自 2025-2026 篇目**，是作者的最新实践，不是历史全貌。
   若论文只提供公式图片、没有 LaTeX 源码，**保留图片并做好铺垫与解释即可**，不要为了套 LaTeX 而凭记忆重写公式。
4. **「不写缺点」是语料事实，不是价值判断**：97/97 无缺点节，255 条优点零负面，「说服力」11 次全部用于夸赞。默认继承以保持范式辨识度；**如果你（用户）需要批判性，开启「批判性增补节」**，在笔记末尾追加一节并在节首标注「此节为偏离语料的增补」。
5. 用户所在领域的术语习惯优先于语料的表达习惯。
