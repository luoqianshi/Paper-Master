## 二、路由规则（if-then）

### R1 默认 → 标准五节
```
研究动机 → 文章贡献 → 本文方法 → 实验结果 → 优点和创新点
```
硬约束：**研究动机、文章贡献必须是前两节且必须存在；优点和创新点必须是末节。**

### R2 插入「预备知识」（25%）
位置：恒在「文章贡献」之后、「本文方法」之前。

```
IF 论文核心 claim 是「把 A 统一 / 等价 / 归约为 B」
   → 必插，且 A、B 两套体系都要形式化写全
ELSE IF 正文反复使用 ≥8 个非通用符号
   → 插，并配「| 符号 | 含义 |」表
ELSE IF 前置概念是通用件（GCN / 自编码器 / 交叉熵）或一句话可讲清
   → 不插，内联带过
```
形态：2-3 个 H3，占全文 5%-17%。**配表是硬约束，配图是软约束。**
降级方案：不单列 H2，而在方法节内嵌「公式中的符号含义如下表所示」。

### R3「本文方法」替换为论文方法名（10%）
判据**不是**方法名的辨识度（反证：DTSemNet、TnT 都是自造名，仍保留「本文方法」），而是**方法名能否统摄方法节下的全部子节**：

```
IF 单一主线、无兄弟方案（如「进化森林算法」）
   → 方法名上提为 H2（注意：常与实验节改名成对发生，如「实验分析」）
IF 方法段需拆 2 个以上 H2
   → 各段用方法名 / 机制短语命名
IF 出现兄弟方案并存（如 TAO vs CART）或有无法冠名的节（定理证明、多任务实现）
   → 退回「本文方法」，方法名下压到 H3
```
代价：丢掉「本文方法」这个检索锚点，跨笔记检索变难。

### R4 多 H2 拆分（4%）
方法含 ≥3 个可命名子模块、且论文自带模块名时，把方法段拆成多个并列 H2。

### R5 加「理论分析」（4%）
```
IF 有形式化定理   → 用「**定理 1.**」「**备注 1.**」加粗环境 + 证明块
IF 无形式化定理   → 用「设问引出 + 结论贴图 + 散文解释段收束」（B06 实证：本批零定理样本）
```
位置：方法节之后，或中置为独立 H2（B12-05 是「测试损失证明 + 复杂度分析」）。

### R6 尾部分析节（6%）
实验结果后追加「XX 分析」H2。常见主题：可解释性分析、复杂度分析、统计显著性检验、可视化分析。

### R7 survey / review 重写（3%）
**不写「优点和创新点」**，改用分类体系骨架。两种实证形态：

| | 神经树 survey（B08-04） | 重采样 survey（B14-回归06） |
| --- | --- | --- |
| H2 序列 | 研究动机 → 非混合 → 半混合 → 混合 → 分析与展望 | 不平衡回归问题 → 本文目标和贡献 → 基本概念和分类方法 → 重采样算法 → 实验研究 |
| 分类体系 | **不用维度表**，靠标题层级承载（H2 大类 → H3 二级 → 正文编号三级） | 用「基本概念和分类方法」节建分类法 |
| 研究问题 | 无 | 「本文目标和贡献」节列 5 条**裸数字编号的完整疑问句**（不用 RQ 前缀） |
| 收尾 | 「分析与展望」：立评估标准 → 重映射范式 → 逐项给局限与未来方向 → 末段「三个最具潜力的发展方向」 | 「实验研究」末 H3「经验总结」：5 条有序列表与 5 个问题**严格一一对应**，措辞为「照抄原问句短语＋全角冒号＋证据＋因此…」，证据不足时答「影响尚不清楚」 |

逐类写法固定为：**定义句 + 代表工作（加粗名 + 一句机制）+「该方法的优势是……局限在于……」对照 + 类末 H3「小结」**（写共性目标、共性局限、与下一类衔接）。

### R8 尾部缺失（2%）
短文（会议短文、2013 年早期工作）省掉优点节，实验末图后直接收尾。这是语料中**唯一**允许省略末节的情形。

## 五、H3 划分的四种逻辑

1. **按模块**（18%）：方法由若干并列组件构成时（如 GRANDE 的「加权树集成 / 可微分分割 / 实例级权重 / 正则化」）
2. **按流程步骤**（23%）：方法是流水线时（如 OpenFE 的「问题定义 → 扩展 → 缩减」）。**视觉类论文多用此逻辑**（按数据流切，而非按模块堆）
3. **按定义 → 结构 → 变体**（12%）：同一对象有多种形态时（如「二分类 RandBal → MultiRandBal → OVO/OVA-RandBal」）
4. **混合**（33%）：方法节用一种、实验节用另一种（如方法按模块、实验按数据集或按任务分节）

全篇只用一种逻辑；若必须混合，也要保证**方法节内部统一**。
