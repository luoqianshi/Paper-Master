# PDF 论文图表精准定位与裁切实现原理

> 提问时间：2026-10-28 15:48:24
> 对应文件：`d:/Data/LQS_Skill/Accumulate-PPTs/.qoder/skills/html-paper-slides/scripts/pdf_extractor.py`

## 问题

`d:/Data/LQS_Skill/Accumulate-PPTs/.qoder/skills/html-paper-slides` 中，是怎么实现精准找到 PDF 论文中的图表的位置，并且进行精准有效的定位裁切的呢？

## 回答

### 总体架构：标题驱动 + 三重过滤 + 视觉精修

整个流程分 3 个阶段，每个阶段都有明确的定位策略和兜底机制：

```
PDF 页面 → [阶段1:标题检测] → [阶段2:区域关联] → [阶段3:边界精修+裁切]
             三重过滤          双向智能搜索         视觉/文本外接矩形
```

---

### 阶段 1：标题检测（三重过滤，排除正文引用）

入口：`detect_all_captions(doc)` → `find_caption_candidates(page)` + `verify_caption_with_visual_content(page, cap)`

<iframe src="./html-vis/stage1_caption_detection.html" width="100%" height="500" style="border:0;border-radius:12px" loading="lazy"></iframe>

> 图示：[阶段 1 标题检测三重过滤](html-vis/stage1_caption_detection.html)（若上方内嵌图未渲染，点击链接单独打开）

**为什么要"三重过滤"？** 学术论文正文里大量出现 "Figure 3 shows that..." 这种引用文本，直接正则匹配会把这些也当成标题。

| 过滤层 | 位置 | 做法 |
|---|---|---|
| **F1 文本模式匹配** | `parse_caption_text(text)` L203 | 先用带标点的正则 `^(Figure\|Fig\.\|Table\|Algorithm)\s+(\d+[a-z]?)\s*[:.。，—–\-]`（高置信），再用无标点正则（低置信，需进一步排除） |
| **F2 动词黑名单排除引用** | `parse_caption_text` L226 | 无标点模式下检查编号后的下一个词是否是 `shows/illustrates/demonstrates/is/we/...` 等正文引用词，命中则丢弃 |
| **F3 邻近视觉内容验证** | `verify_caption_with_visual_content` L351 | **最关键的一层**：真正的图表标题旁边一定有视觉内容。它会在标题上/下的搜索区域里检查是否存在矢量绘图或内嵌图片，没有则判定为正文引用并过滤 |

**视觉内容从哪来？** `get_page_visual_regions(page)` L124 做了两件事：

- `page.get_drawings()` → 提取 PDF 中所有**矢量绘图对象**的 `rect`（图表中的线条、矩形、曲线等）
- `page.get_image_info()` → 提取所有**内嵌位图**的 `bbox`
- 两者合并后用 `merge_rects(regions, overlap_threshold=0.2)` 把重叠矩形合并，过滤掉太小（面积 < 3000）或太大（占页面 > 50%）的噪声

### 阶段 2：区域关联（智能双向搜索 + 搜索边界约束）

入口：`compute_search_area(cap_bbox, direction, text_blocks, pw, ph)` L278

找到标题后，要确定"图在标题旁边的哪个方向"以及"搜索范围有多大"。

<iframe src="./html-vis/stage2_region_search.html" width="100%" height="500" style="border:0;border-radius:12px" loading="lazy"></iframe>

> 图示：[阶段 2 区域关联双向搜索](html-vis/stage2_region_search.html)（若上方内嵌图未渲染，点击链接单独打开）

#### 方向策略（`verify_caption_with_visual_content` L351）

```
Figure 标题 → 默认向上找（标题通常在图下方），找不到再向下兜底
Table/Algorithm 标题 → 双向都找，取最优方向
  - 优先：搜索区域里有矢量/图片视觉内容
  - 其次：搜索区域里有 ≥2 个短文本单元格（无边框表格）
```

#### 搜索区域边界（核心约束逻辑）

**水平方向** — `_compute_horizontal_range` L185

- 标题宽度 > 页宽 60% → 全宽搜索（跨栏图表）
- 否则 → 限制在标题所在栏（标题 x 范围 ±20pt）

**垂直方向** — `compute_search_area` L295-343

| 方向 | 上边界 | 下边界 |
|---|---|---|
| **向上 (Figure)** | 从上往下扫描上方文本块，遇到**另一个标题**就停（`parse_caption_text(t) is not None`）；没遇到就用 `PAGE_MARGIN_TOP=50`；最后 clamp 到 `MAX_SEARCH_DISTANCE=550pt` | 标题上边缘 |
| **向下 (Table)** | 标题下边缘 | 三级收缩策略：① 遇到 >18pt 间隙就停；② 遇到 >120 字符的段落就停；③ 都没遇到就用最后一个文本块底部；最后 clamp 到 `MAX_SEARCH_DISTANCE=550pt` |

这个设计的精髓在于：**向上搜用"上一个标题"当边界，向下搜用"间隙/段落"当边界** —— 因为 Figure 标题的上方很可能是上一个 Figure 的标题，而 Table 标题下方跟数据之间可能有边框间隙。

### 阶段 3：边界精修 + 裁切（`refine_crop_region` L458）

搜索区域只是一个**粗略范围**，真正裁切时需要精确到像素。精修逻辑：

<iframe src="./html-vis/stage3_crop_region_refinement.html" width="100%" height="500" style="border:0;border-radius:12px" loading="lazy"></iframe>

> 图示：[阶段 3 边界精修与裁切](html-vis/stage3_crop_region_refinement.html)（若上方内嵌图未渲染，点击链接单独打开）

```
搜索区域内的视觉区域（矢量+图片）
        ↓
  用 fitz.Rect & 做矩形与运算（裁剪到搜索区域内）
        ↓
  取所有相交视觉区域的外接矩形 (min x0/y0, max x1/y1)
        ↓
  加 5pt padding → 最终 crop_rect
```

**如果搜索区域里没有视觉区域（无边框表格）**，降级为：

```
搜索区域内的所有文本块 → 取外接矩形 → +5pt padding
```

最后用 PyMuPDF 的 `page.get_pixmap(matrix=mat, clip=crop_rect, alpha=True)` 做精准渲染，`zoom = dpi/72`（默认 200 DPI）。

#### 裁切后的质量防线

| 检查 | 阈值 | 处理 |
|---|---|---|
| 最小像素尺寸 | 宽 ≥80px, 高 ≥80px | 跳过 |
| 最小文件体积 | ≥2048 字节 | 过滤（空白/噪声） |
| 盲裁剪 fallback | `--fallback-blind-crop` | 标题驱动失败后启用 |

---

### 兜底机制：盲裁剪（`extract_figures_blind_crop` L635）

当标题驱动完全没找到时启用，纯视觉驱动：

- 每页收集所有视觉区域（矢量+图片）
- 过滤：太小/太大/在页眉页脚位置/极端宽高比/与已有区域重叠 >70%
- 按面积排序，每页最多保留 5 个最大的
- 输出 `crop_XXX_pageYYY_regZZ.png`，文件名无语义但能兜底

---

### 坐标系要点

这个脚本**全程只用 PyMuPDF 的坐标系**，没有跨库所以不存在 "pdfplumber 左下 vs PIL 左上" 的坑。PyMuPDF 的 `Rect` 就是 PDF 原生坐标系（y 轴原点在页底），直接传给 `clip` 参数就行，不需要 y 翻转。如果将来要导出到 PIL 再处理，才需要做 `page.height - y` 的翻转。

### 一句话总结

> **先用正则 + 动词黑名单 + 邻近视觉验证精准定位标题，再按"Figure 向上 / Table 向下"的版面惯例，用文本块间隙和标题边界收缩出合理搜索窗口，最后在窗口内收集矢量/图片视觉对象取外接矩形做像素级裁切。** 每个环节都有明确的阈值和降级策略，从"找标题"到"定范围"到"收边界"是层层收缩的漏斗形设计。

---

### 关键常量速查

| 常量 | 值 | 用途 |
|---|---|---|
| `PAGE_MARGIN_TOP` | 50.0 pt | 向上搜索的兜底上边界 |
| `PAGE_MARGIN_BOTTOM_RATIO` | 0.95 | 向下搜索的兜底下边界（页高比例） |
| `PAGE_MARGIN_LEFT` / `RIGHT` | 30.0 pt | 页面左右安全边距 |
| `MAX_SEARCH_DISTANCE` | 550.0 pt | 单次搜索的最大垂直跨度 |
| `TABLE_GAP_THRESHOLD` | 18.0 pt | 表格与正文的分界间隙 |
| `TABLE_CELL_TEXT_MAX_LEN` | 120 字符 | 区分表格单元格与正文段落 |
| `VISUAL_MIN_WIDTH` / `HEIGHT` | 30 pt | 视觉区域最小尺寸 |
| `VISUAL_MIN_AREA` | 3000 pt² | 视觉区域最小面积 |
| `MIN_CROP_WIDTH_PX` / `HEIGHT_PX` | 80 px | 裁剪结果最小像素尺寸 |
| `MIN_FILE_SIZE` | 2048 字节 | 裁剪结果最小文件体积 |
