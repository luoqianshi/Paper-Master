ABSTRACT

摘要

Existing Real-Time Object Detection (RTOD) methods commonly adopt YOLO-like architectures for their favorable trade-off between accuracy and speed. However, these models rely on static dense computation that applies uniform processing to all inputs, misallocating representational capacity and computational resources such as over-allocating on trivial scenes while under-serving complex ones. This mismatch results in both computational redundancy and suboptimal detection performance. To overcome this limitation, we propose YOLO-Master, a novel YOLO-like framework that introduces instance-conditional adaptive computation for RTOD. This is achieved through an Efficient Sparse Mixture-of-Experts (ES-MoE) block that dynamically allocates computational resources to each input according to its scene complexity. At its core, a lightweight dynamic routing network guides expert specialization during training through a diversity enhancing objective, encouraging complementary expertise among experts. Additionally, the routing network adaptively learns to activate only the most relevant experts, thereby improving detection performance while minimizing computational overhead during inference. Comprehensive experiments on five large-scale benchmarks demonstrate the superiority of YOLO-Master. On MS COCO, our model achieves 42.4% AP with 1.62ms latency, outperforming YOLOv13-N by +0.8% mAP and 17.8% faster inference. Notably, the gains are most pronounced on challenging dense scenes, while the model preserves efficiency on typical inputs and maintains real-time inference speed.

一句话概括：把 Mixture-of-Experts 的条件计算 装进 YOLO，让每个输入按场景复杂度决定激活多少专家。

01 · 研究动机

被“静态稠密计算”锁死的一刀切

01

简单场景在浪费

稀疏、大目标的简单画面，与密集小目标的复杂画面占用同一份计算预算，导致资源冗余与特征纯度下降。

02

复杂场景不够用

网络容量在训练前固定，无法针对高密度、多尺度输入临时扩容，复杂场景的表征供给不足。

03

精度—速度被预设

从 YOLOv1 到 YOLOv13，架构与训练策略不断演进，但计算路径和预算始终在 design time 固定。

原文判断：现有 YOLO 系列与 RT-DETR 都采用 static dense computation，输入复杂度不会改变网络路径与算力分配。

启示来源：大语言模型中的稀疏激活（不同输入激活不同参数子集）能否迁移到实时目标检测？
02 · 文章贡献

四项贡献：从“静态容量”到“条件计算”

01

首个 RTOD 的 MoE 条件计算框架

用动态专家激活让模型容量随输入复杂度变化，正面挑战静态精度—效率权衡。

02

ES-MoE：多尺度专家 + 动态路由

深度可分离卷积构成 3×3 / 5×5 / 7×7 等不同感受野专家，由轻量路由网络按实例选择。

03

面向检测的负载均衡监督

抑制 expert collapse，保持专家利用率均衡，同时不牺牲推理阶段的真实稀疏性。

04

五个基准的系统验证

MS COCO、PASCAL VOC、VisDrone、KITTI、SKU-110K 上的一致提升，覆盖不同目标密度与视觉域。

核心命题：模型容量不应由设计时固定，而应由输入复杂度现场决定。

03 · 相关工作

三条脉络，一个共同缺口

A

实时检测器

  • YOLO 系列：多尺度金字塔、ELAN、NMS-free、选择性注意力、超图感知
  • RT-DETR 等 Transformer 检测器同样采用静态计算
  • 改进集中在骨干、融合与训练范式，缺少按输入分配资源的机制
B

Mixture of Experts

  • 门控网络把输入路由到专家子网络，已在语言模型规模化中奏效
  • 视觉侧多用于 ViT 分类与多任务学习，检测等稠密预测仍少见
  • ViT 检测器的 MoE 尝试带来较大开销，不适合实时场景
C

自适应特征处理

  • SE、CBAM、自注意力按内容重标定特征
  • 但计算仍对所有输入一视同仁，属于输入无关的静态架构
  • 高效注意力降低了复杂度，本质上仍是稠密处理

缺口：面向 轻量 CNN 实时检测器、在特征金字塔上做 多尺度条件路由，并把训练与推理的稀疏策略解耦。

06 · 动态路由与门控

轻量路由：先看全局，再分专家

wi = exp(gi(X)) / Σj=1E exp(gj(X))
(1)
Λ = Conv1×1out=E( SiLU( Conv1×1out=Cred(P) ) )
(5)
P = GAP(X) ∈ RC×1×1，Cred = max(C/γ, 8)，γ = 8。
  • 全局信息聚合：用 GAP 把 C×H×W 压成 C×1×1 的全局描述子，给整张特征图统一的路由依据。
  • 两级 1×1 卷积：Cin → Cred → E，中间加 SiLU，通道缩减比 γ = 8，避免门控本身成为瓶颈。
  • 与空间尺寸解耦：logits 只依赖通道数 C 与专家数 E，不随 H×W 增长，高分辨率特征也能低成本路由。

路由的产物只有 E 个标量权重，却决定了一整张特征图走哪几条专家路径。

原文默认配置：E = 4 个专家，K = 2（依据 §4.3.2 与 §4.3.3 的消融结论）。
07 · 专家网络

用深度可分离卷积铺开多尺度感受野

  • 轻量基元：每个专家用 DWconv 代替标准卷积，把空间滤波与通道整合解耦，参数量与 FLOPs 同时下降。
  • 异构核尺寸：ki ∈ {3, 5, 7, …}，不同专家覆盖不同范围，路由可按需挑选局部或更大上下文。
  • 同分辨率输出：Yi ∈ RCout×H×W，所有专家输出按路由权重 ωi 加权求和。
Experti(X) = DWconvki, Cin→Cout(X)
(3)
YMoE = Σi=1E ωi · Yi
(4)
3×3

小核专家：聚焦局部纹理与边缘，适合小目标与细结构。

5×5

中核专家：兼顾局部细节与邻域上下文，覆盖中等尺度目标。

7×7

大核专家：扩大有效感受野，为密集、大尺度或遮挡场景补上下文。

专家不是同构副本，而是 不同感受野的功能分工；路由决定这一刻谁上场。

08 · 分阶段路由

训练要梯度，推理要真稀疏

TRAINING · SOFT TOP-K

保留梯度连续性

  • 先对全部 logits 做 Softmax，得到 Ω′
  • 按权重选出 top-K，构造二值掩码 MK
  • 掩码后只保留 K 个非零权重并重新归一化
  • Ω′ 参与计算，因此权重对 logits 仍可导
INFERENCE · HARD TOP-K

只算被选中的专家

  • 直接取 top-K 的 logits ΛK
  • 仅对这 K 个 logits 做 Softmax
  • 其余 E − K 个专家权重严格置 0
  • 前向只调用 K 个专家，硬件上获得实际加速
Ωtrain = Ω′ ⊙ MK / ( Σj (Ω′)j ⊙ (MK)j + ε )　(8)　　Ωinfer,i = exp(Λi) / Σj∈IK exp(Λj)　(9)
模式切换由 self.training 决定（Eq.10）：训练走 Ωtrain，推理走 Ωinfer。
09 · 损失函数

检测损失 + 负载均衡

LTotal = LYOLO + λLB · LLB　　LYOLO = Lcls + Lloc + LDFL　(11)

负载均衡损失 LLB

先统计专家 i 在当前 batch 与全部空间位置上的平均利用率 μi，再惩罚其与理想均匀分布 1/E 的偏差。

LLB = (1/E) Σi=1E ( μi − 1/E )2　(13)

为什么需要它

  • MoE 训练常见的 expert collapse：路由把大多数 token 压给少数“更强”专家
  • LLB 让所有 E 个专家都被充分训练，提升泛化与鲁棒性
  • λLB > 0 控制均衡项权重，与检测损失共同优化

最终配置（Table 8 · Config 5）：去掉 DFL、只保留 MoE 损失且权重 1.5，取得 62.2% mAP。

注：LYOLO 的定义含 DFL，但最终配置移除了 DFL，原文将这一取舍解释为 DFL 与 MoE 损失存在梯度竞争。

12 · 精度—延迟

把帕累托前沿再往前推一步

  • 对 YOLOv13-N：COCO +0.8、VOC +1.4、VisDrone +2.1、KITTI +1.5、SKU-110K +0.7（mAP）。
  • 速度：1.62 ms，比 YOLOv13-N 的 1.97 ms 快 17.8%（§4.2 写作 18%）；仅比最快的 YOLOv11-N（1.50 ms）慢 8%。
  • 增益分布：最大提升出现在 VisDrone 与 KITTI，对应小目标检测与精确定位。
  • 密集场景：SKU-110K 平均 147 个目标/图，仍达 58.2% mAP。

结论：精度提升没有以实时性为代价，条件计算在典型输入上保持效率。

15 · 训练动力学

为什么去掉 DFL 反而更稳

  • 冲突假设：DFL 追求基于均匀分布的精修，MoE 损失鼓励实例自适应专家分化；两者权重都大时互相竞争梯度。
  • 现象：Figure 3 中 Config 4（DFL + 强 MoE）振荡明显，Config 5（MoE-only）收敛平滑。
  • 结果：Config 5 在验证集达到 62.2%，Config 1 为 61.9%。
  • 作者解释：MoE 损失可能“吸收”了 DFL 在框回归上的作用。

这是一个 反直觉但可复现 的配置结论；原文仅给出梯度冲突的假设，未做进一步归因实验。

17 · 定性分析

四类困难场景下的可视化对比

  • 小目标：草地远景小动物，v10–v11 漏检，v12 为 0.47、v13 为 0.53，YOLO-Master 达 0.65–0.82。
  • 类别混淆：海岸岩石旁被遮挡的人，前代漏检或勉强检出，YOLO-Master 给出准确框。
  • 复杂场景：剪羊毛场景动物重叠、人机交互，检测更干净；正文称平均置信度 0.85，v13 为 0.77。
  • 密集场景：餐桌瓶、杯、餐具大量重叠，覆盖更完整；正文称置信度 0.87–0.97。

定性结论：专家分工对遮挡、密集与小目标更有效，平均置信度与覆盖度更高。

18 · 结论与讨论

把稀疏 MoE 成功接到稠密预测任务上

01

结论

ES-MoE + 轻量动态路由，让实时检测器按输入复杂度分配容量；Soft / Hard Top-K 分阶段切换兼顾训练稳定与推理稀疏。

02

原文的边界

论文未设“局限”章节：训练硬件型号缺失；仅报告激活 K 个专家时的 Params；延迟为专用加速器 FP16 / batch 1，未给边缘设备实测。

03

展望

作者希望把条件计算扩展到检测之外的视觉任务，并走向资源受限设备上的高效实时视觉系统。

可迁移的启示：“按需算”比“一律算”更适合真实世界中复杂度高度不均的输入分布。

以上“边界”为依据原文信息缺口的客观归纳，非作者自述；论文正文没有 Limitations 小节。
