YOLO-PEFT:
Parameter-Efficient Fine-Tuning
on YOLO Family

把 adapter 放置建模为「训练前可审计、可拒绝」的约束规划问题 —— 面向异构检测器家族的结构感知 PEFT 框架

Overview · Contributions

核心贡献

01

放置 = 可审计的约束规划

不再提出新的低秩参数化，而是把 adapter 放置建模为约束规划问题：先解析出带算子角色与语义角色的类型化图，再用有界的十维架构指纹刻画检测器结构

02

固定顺序约束 + 预算秩分配

按固定顺序施加算子有效性、检测语义、图接口、架构策略与预算可行性约束，在幸存目标上求解预算感知的秩分配，并在校准覆盖内估计失败风险

03

统一运行时 + Refuse 机制

被接受的方案落入训练-保存-合并-导出统一运行时；约束无可行交集或校准预测到灾难性退化时返回 Refuse，并把 Full-SFT 作为一等回退结果

04

实验：适配器超越全量微调

VOC 官方协议下，规划器选出的 RS-LoRA 在 YOLO11s / YOLO12s 达到 0.7138 / 0.7307 mAP50-95，均超过 Full-SFT 的 0.6428 / 0.6662；RT-DETR-L 上七种 LoRA 族配置全部触发校准拒绝

Motivation · 1/2

研究动机：部署需要持续再适应，但 PEFT 迁移有风险

目标检测模型的规模化部署是对同一套预训练权重的持续再适应过程：新的类别词表、领域、传感器、时延目标和硬件后端都要求反复微调——全量微调需要为每个部署变体复制完整的训练状态与检查点，PEFT 因此成为降低适配与分发成本的重要手段

⚠ 异构的检测器计算图

现代检测器交错出现稠密卷积、分组卷积与深度可分离卷积，还包含与损失耦合的 DFL 投影、可变形注意力、文本-图像融合与 MoE 路由

⚠ 为同构 Transformer 设计的 PEFT

大致同构的 Transformer 栈上的 PEFT 方法并不能安全迁移到异构检测器上：不加甄别地插入 LoRA 可能引发优化失败或严重的 mAP 退化

Motivation · 2/2

现有方案留下的四个缺口

G1

无放置前检查

通用 PEFT 接口按模块名称或类型选择目标，训练前不检查算子契约、检测语义、图接口与放置风险

G2

专用方法缺统一抽象

SpotPatch、LoRA-Det、YOLO-IOD 等检测器专用方法证明了选择性适配的价值，但放置策略绑定在特定检测器、任务或组件上，缺乏跨越卷积、Transformer、多模态与 MoE 图的统一抽象

G3

无端到端部署契约

放置本身不提供覆盖训练、adapter-only 检查点、合并与 ONNX/TensorRT 导出的契约，部署兼容性依赖方法特定的集成

G4

无校准机制

已有接口没有校准机制在高风险的架构-adapter 组合进入完整训练之前识别它们，失败主要依靠代价高昂的试错来发现

暂未有工作在异构检测器家族上，给出一个训练前可审计、可拒绝的 adapter 放置规划框架。

Method · Formalization

问题形式化：把放置定义成带约束的决策问题

Placement Definition

π : Vcand → {0} ∪ K    P(G, R, B) = (d, π, J),  d ∈ {Accept, Refuse}

π(i)=0 表示第 i 层保持冻结；π(i)=r ∈ K 表示给该层分配一个秩为 r 的 adapter。G 为检测器对应的有向无环图，R 为 PEFT 请求，B 为 adapter 参数预算，J 为有序拒绝日志

  • 直观上，合法方案必须同时满足算子有效性、检测头语义安全、图接口兼容、参数预算可行与部署兼容五类约束
  • 这一设计使接受与拒绝都可审计：被接受的方案同样记录被排除的模块
  • 拒绝则至少返回一个终结原因码，从而区分「不支持」与「预测不准」，避免同一个 Refuse 掩盖不同成因
符号含义
G=(V,E)检测器对应的有向无环图
R=(p,T,L,K)PEFT 请求：变体、可选目标集、可选层区间、允许秩集合
Badapter 参数预算
zi=(oi,si,qi,hi)模块 i 的算子、语义、图接口与部署元数据
φ(G)检测器的十维架构指纹
J有序拒绝日志
Method · Parsing & Fingerprint

角色感知的图解析与十维架构指纹

双重角色：同一个 Conv2d 命运不同

同一个 Conv2d 可能属于骨干块、特征金字塔融合、回归头或固定的 DFL 投影——仅凭 Python 类型不足以判定它是否为安全目标

  • 算子角色＝计算契约：稠密卷积接受普通低秩因子；分组卷积要求组内局部因子；深度卷积不能接受跨通道混合的更新；归一化、激活与未知算子保守处理
  • 语义角色＝检测器含义：固定 DFL 投影、几何敏感的回归路径与 MoE 路由被排除——微小更新就可能改变校准好的分箱或专家分配

有界十维架构指纹 φ(G)

支撑架构级风险分析，五个核心维度为：

φcore = (φattn, φtext, φmoe, φdw, φconv)

φattn = |attention| / |Vrole| 度量注意力模块相对占比，φdw 同理度量深度卷积占比；其余三维度量文本融合、MoE 专家与稠密/分组卷积占比

  • 另外五维编码深度、宽度、头参数比、残差密度与归一化类型
  • 解析器能识别 YOLO12 Area-Attention、RT-DETR 可变形注意力、YOLO-World 文本融合与 MoE 路由；未知模块一律获得 unknown 角色且不被适配
Method · Constraints

约束接口与硬约束过滤

  • 按固定顺序施加约束：过滤算子 → 过滤语义 → 应用架构策略 → 分配秩 → 校验可靠性；有效性检查先于效率优化
  • 先移除深度卷积、归一化/激活与未知算子；对分组数为 G 的分组卷积，总秩按 r = Σg=1..G rg 分配，均衡分配取 rg = r/G，因此要求 G ∣ r
  • 随后移除固定 DFL 投影、MoE 路由与几何敏感的回归路径
  • 用户指定的目标集 T 与层区间 L 只在强制过滤之后做交集——显式请求无法重新启用不安全模块

表中每一行约束都消费特定的元信息、执行确定性的接受规则，失败时返回明确的原因码：分组卷积秩不可整除返回 E-GROUP-RANK、固定 DFL 返回 E-DFL-FIXED

六类约束的正式接口，每类输入元信息、输出接受决策或原因码
Method · Architecture-Conditioned Policy

架构条件策略与端到端示例

家族级策略（只对已校准家族生效）

Method · Rank Allocation & Calibration

预算化秩分配与可靠性校准

预算约束下的效用最大化

maxπ Σi∈Vcand u(i, π(i); p, φ)
s.t.  Σi cp(i, π(i)) ≤ B

clinear = br(din+dout)；cconv = br(Cinkhkw+Cout)；rule-only 模式 u = uop+usem+urange+urank − λcp，效用非正的候选对直接丢弃

例：Cin=Cout=256、3×3 稠密卷积宿主、FP16（b=2）、r=16 → cconv = 2×16×(256×9+256) = 81920 字节。单个卷积宿主的秩成本与输入通道数和核面积线性相关，规划器据此决定把 adapter 装到哪几层

校准模式：预测 ΔmAP

ΔmAP ≈ β0 + β1φattn + β2φtext + β3φdw + β4ξp

β₀ 为截距，β₁–β₃ 为注意力、文本融合与深度卷积占比系数，ξp 为标准矩阵上拟合的变体系数

  • 预测值用于审计，低于 −0.05 灾难阈值时触发拒绝
  • rule-only 仍是默认模式；LOVO 评估只覆盖已观测架构，不外推到未见家族
Method · Runtime & Export Contract

YOLO 兼容运行时与导出契约

四个不变量

  • I1 基座检查点加载方式不变
  • I2 adapter 检查点只存 adapter 张量与运行时元数据
  • I3 合并后恢复普通 YOLO 模块
  • I4 ONNX 与 TensorRT 导出器看到导出兼容的图

双后端 · 同一接口与生命周期

HuggingFace PEFT 处理 LoRA、RS-LoRA、DoRA、LoHa、LoKr、AdaLoRA、IA3、OFT、BOFT 与 HRA 十种变体；更窄的仓内后端在 PEFT 不可用时提供纯卷积 LoRA

共享生命周期：优化器构建前安装 → 冻结基座训练 → 只保存 adapter 状态 → 加载到兼容基座 → 合并 → 移除包装再导出；adapter 未合并期间卷积融合被禁用

Grouped-Conv Merge Equivalence

ΔWg = BgAg⊤  重塑到宿主核对应分区  →  W0 ← W0 + sΔW

每个组内更新被独立构造，移除包装后卷积输出与包装模块等价至浮点容差——保证规划器输出的方案在部署侧真实可用

Method · Training Strategies

四个可选训练策略（不改变放置）

S1

层级学习率衰减

ηℓ = η0 ρdℓ，其中 ρ = 0.85、dℓ 为归一化深度——使早期特征提取器收到的更新更小

S2

Alpha Warmup

LoRA 缩放 α/r 从零经余弦调度升到目标值，避免满强度的随机 adapter 在训练初期扰动注意力密集的检测器；YOLO12 护栏要求至少三个 warmup epoch

S3

正交正则

每隔 N 个 batch 加入 λortho(‖A⊤A − I‖F + ‖B⊤B − I‖F)，λortho = 0.5；A、B 为 LoRA 两个低秩因子，分块计算限制多个 adapter 同时激活时的内存开销

S4

动态 Dropout

前 30% 的 epoch 结束后，把 adapter dropout 率从 0 线性升至 0.15——早期保留梯度信号、后期施加正则

各策略可通过 LoRAConfig 独立启用，完整的分量消融在补充材料中报告

实验设置：官方 VOC 协议 · 五种异构架构

数据与训练配置

Experiments · Stability

灾难率随注意力占比上升 → 校准拒绝

五架构诊断扫描热图：红色单元表示灾难配置（Δ < −0.05），灾难率随 φattn 上升——CNN-only 的 YOLO11n 上标准变体 10 次运行零崩溃，YOLO12n 升至 6/7，RT-DETR-L 达到 7/7

排序不稳定

成对 Kendall-τ 分析显示变体排序跨家族减弱或反转——评估的家族内不存在通用的 PEFT 排序

YOLO-World 机制

图像与文本分支梯度范数相差数量级，DoRA 的幅度分解放大失配，15 个 epoch 内损失发散（Δ = −0.292）

拒绝的价值

RT-DETR-L 七个配置全部低于阈值，返回最不坏的 adapter 也只是错误接受——拒绝避免了七次完整的训练尝试

Experiments · Efficiency

效率审计：显存省 43.9%，时间换 1.72 倍

受控 YOLO11 系统审计：LoRA 的峰值训练显存从 28.57 GB 降到 16.03 GB（降低 43.9%），但训练时长从 118.2 s 增加到 203.8 s（1.72 倍），其他 PEFT 变体也都慢于 Full-SFT

显存的节省以优化时间换来——论文据此把显存、时间与合并/未合并行为作为三个独立资源轴分开报告

Experiments · Ablation

规划器约束消融与秩敏感性

YOLO12s 上的组件消融：无约束基线 0.6900 → 加入算子有效性过滤 0.7094 → 再加入检测头语义排除跃升到 0.7307
  • 语义守卫是稳定性的主要驱动，而非单纯的工程护栏
  • 秩敏感性：r = 8 / 16 / 32 对应 0.7288 / 0.7307 / 0.7363
  • r = 32 收益递减且参数与计算开销明显增大
  • r = 16 是实际的 Pareto 默认点

Summary · Strengths

优点与创新点

01

可审计的约束规划

把 adapter 放置从隐藏的手写目标列表改造成可审计的约束规划问题：每次排除都有明确原因码与有序拒绝日志，能够区分「不支持」与「预测不准」两种拒绝，工程上可追溯、可复核

02

Refuse 是一等结果

把 Refuse 提升为一等的规划结果并配套可靠性校准：在 RT-DETR-L 七个全部灾难性的配置上避免了七次无效的完整训练；实验覆盖 14 个 PEFT 变体与 5 个异构检测器架构，说服力强

03

端到端契约真正落地

训练-保存-合并-导出的端到端契约配上分组卷积合并等价性证明：合并后计算图恢复基座算子开销，ONNX/TensorRT 导出校验通过，受控审计下峰值训练显存降低 43.9%

Discussion · Limitations

局限与批判性讨论

此节为偏离语料的增补
01

证据限于 VOC 协议

全部核心证据限于官方 VOC07+12 → VOC07 test 协议，论文明确承认不支持关于 COCO、域移、少样本或方差的任何结论，跨域泛化仍是待验证问题

02

架构级误拒/误受率无法给出

没有任何检测器家族被留出，「基于该矩阵无法计算未见架构上的真实误拒率」；variant 级 LOVO（准确率 86.7%、F1 0.850）不等于架构级验证

03

校准不外推

可靠性校准是在标准矩阵上拟合的线性预测式，覆盖外只能返回 unsupported 而非外推安全保证；对全新检测器家族的拒绝验证被列为开放问题

04

效率交换与兼容性边界

LoRA 省下 43.9% 峰值显存的同时训练耗时变为 1.72 倍；MoE 压力测试中 BOFT 与 OFT 直接失败且无指标，兼容性并不覆盖全部变体。另：主矩阵为 seed-0 结果（多种子 std ≤0.006），自述「不是配对显著性检验」，结论应理解为受控相对比较
